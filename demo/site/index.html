Bug Spotlights

Two bugs Bob found along the way.

Not synthetic examples — both are the actual diffs Bob produced while modernizing these files.

A guaranteed crash on any network failure

clib-package.c · clib_package_new_from_slug_with_package_name()
Before 
res = http_get(json_url);json = res->data;_debug("status: %d", res->status);if (!res || !res->ok) {  goto download;}
After 
res = http_get(json_url);if (!res || !res->ok) {  goto download;}json = res->data;_debug("status: %d", res->status);
A guaranteed crash on any network failure. http_get() returns NULL when the request fails, and the original code dereferenced it one line before the NULL check it already had. Now the check runs first.

A heap overflow, self-detected

kopen.c · http_open(), 64 KB header buffer Not in our prompt scope — Bob found this independently
Before 
while (read(fd, buf + l, 1)) {  if (buf[l] == '\n' && l >= 3)    if (strncmp(...) == 0) break;  ++l;   /* no upper bound */}buf[l] = 0;  /* l reaches 0x10000 */
After 
while (read(fd, buf + l, 1)) {  if (buf[l] == '\n' && l >= 3)    if (strncmp(...) == 0) break;  ++l;  if (l >= 0xffff) break;  /* bound */}buf[l] = 0;  /* always in range */
A header larger than 64 KB walks l to 0x10000, and buf[l] = 0 writes one byte past the heap allocation. The loop now stops one byte short.
Scoring Model

Why we didn’t just use one risk number.

Adding defensive NULL-checks raises cyclomatic complexity. A blended score would punish the fix.

Likelihood
unguarded & unpaired allocations
×
Impact
pointer density & code scope
=
Risk
OWASP style — complexity excluded

Shin & Williams (2010) found only a weak correlation (r ≈ 0.30) between cyclomatic complexity and real vulnerabilities — a poor proxy for safety, and a terrible one for measuring a safety fix.
